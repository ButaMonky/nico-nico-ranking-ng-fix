# 追加カードプレビュー実装計画

利用者から修正・実装・記録整備まで委任済み。設計は [preview-design.md](../../preview-design.md)。既存の分離済みworktreeで実行し、GitHub送信は行わない。

1. ページ斜線を独立した160.18として保存する。訪問済み3→1で全件処理後に2–26へ統合、未表示3/27の保護、設定変更、公式ルーター復帰をテストする。
2. `src/preview/preview-data.js` と合成unit試験を分担。契約は `PreviewData.load(id,{signal,fetch,report})` と `PreviewData.comments(data,{signal,fetch,report})`。返却は映像URL・期限・長さ・コメント定義、正規化コメント。型矛盾・未対応URL・期限切れ・中断後応答・各HTTP失敗をテストする。
3. `src/preview/hover-preview.js` と模擬ブラウザ試験を実装する。`HoverPreview.create(page,config,options)` が `dispose()` と匿名 `snapshot()` を返す。optionsで合成fetch/mediaを注入可能とする。200ms未満、OFF、公式カードは要求0。同時1、離脱、古い応答、ID差替え、hidden、NG非表示、SPA破棄で残存資源0をテストする。
4. 設定に既定OFFの試験機能を追加し、bootstrapでルートに接続・破棄する。診断には固定キーの数値だけを追加。タイトルや投稿者や通常のカードリンクは書き換えない。
5. HLS.jsの版・hash・ライセンスを記録し、ビルドの再現性検査を追加する。依存は遅延初期化し、外部スクリプト取得を要求しない。
6. 公開文書を分担し、CHANGELOG、TASKS、CONTRIBUTING、PR/不具合テンプレートを整える。実装・試験・実サイト確認・公開状態を区別する。
7. 全unit、該当ブラウザ回帰、構文、個人情報検査、独立レビューを完了する。160.19試験版と160.18安定修正の導入案内を作る。実サイトの未確認条件と次の最小確認を報告する。

## 実行記録

1〜6は実装・合成検証済み。160.18は153件、160.19は166件の自動試験と11種類の模擬ブラウザ試験を実施。独立レビューの指摘を修正し、7の実サイト確認以外を終える。現在の認証・CORS等の確認待ちはTASKSのNRN-002に残し、模擬試験と混同しない。HLSは別音声が必要なためlightではなく完全版を採用し、自作の映像・音声による実エンジンの試験を追加した。
