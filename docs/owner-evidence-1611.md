# 160.11 後から表示される投稿者情報の反映

160.10では、動画カードを最初に解析する時点に投稿者欄がないと、その後に正規の投稿者欄が表示されてもIDを補完できなかった。160.11では既存の画面変更監視から該当カードだけを再確認する。

## 動作

- 正規の投稿者行の追加、リンク先の更新、空欄からの名前の表示を検知。同じ動画の投稿者情報だけをNGモデルに渡す。
- 新しいAPI通信や定期巡回は追加しない。同じフレームの変更をまとめ、ID・名前が同じならモデルの変更通知を出さない。投稿者のURL・文字だけの変更ではページ全体を再解析しない。
- 詳細表示の投稿者名と通常のID NG・複合NGへ反映する。検索結果の名前が最初から空欄だった場合も後から補える。
- 元の投稿者欄が作り直されたときも、詳細を開いている間の二重表示を防ぐため、現在の欄へ表示状態を反映する。元の欄は移動しない。
- 詳細APIの確定IDを優先する方針は維持。検索結果のIDが以前の根拠と矛盾した場合は、名前で推定せず検索由来のIDを未確定に戻す。
- 監視時と反映直前に検索URLを確認する。破棄済みカードや、動画IDが使い回されたカードを旧モデルへ反映しない。

## 検証

自動テスト107件、構文確認、専用Chromeの投稿者補完・カード表示・SPA・リスト／タイル切替の試験が通過。

投稿者試験では詳細APIの投稿者IDを空にし、後から正規の投稿者行を追加してNGが反映されること、名前の遅延表示、追加通信なし、同じ情報の繰り返しで変更通知が増えないこと、矛盾したURLで補完を解除すること、検索URL変更後に古いモデルを更新しないことを確認した。

すべて架空URLと通信を置き換えた空プロファイルでの検証。実ニコニコ・利用中のTampermonkeyへの反映は未実施。
