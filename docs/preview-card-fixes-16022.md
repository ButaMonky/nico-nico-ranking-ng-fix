# 160.22 カードとプレビューの組合せ修正

2026-09-20。160.21を基点とするローカル修正。GitHub未送信。

## 調査結果

利用者提供の保存HTMLと画像で、元カードと追加カードのNG操作欄の位置が異なり、追加カードでは画像の上に帯が重なっていた。公式の音量ボタンを含むホバー要素とrecentTimeColorは前回の保存HTMLにも存在した。資料が欠けていたのではなく、実装と組合せ検証に不足があった。

既存CSSは `.d_grid > [data-anchor]` の子のNG操作欄を上に置くが、追加カードには `data-anchor` がないため `top:0; z-index:11` となる。プレビューの音量ボタンを覆うことを、実際のListPage・MovieRoot・ActionPane・HoverPreviewを使った回帰試験で再現した。元カードの属性を偽って付け足さず、追加カードの操作欄だけを `bottom:100%` でカードの上へ配置する。

追加カードの投稿時刻は表示文字だけを生成し、色と日時属性を設定していなかった。保存された公式Formatのrecent条件は24時間未満。`--colors-text-on-layer-accent-lust` を使用し、24時間以降は既存の本文補助色を継承する。datetimeとtitleもDOM APIで設定する。

今回の匿名診断はplaying=1、comments要求=1、commentsUnavailable=0だったが、実際の描画の有無までは判別できなかった。利用者は再確認後「ホバー時に動画の上をコメントが流れた」と報告した。コメント処理は変更しない。

## 検証方法

`scripts/test-preview-card-integration.mjs` は外部通信を全て模擬応答に置き換えた独立ブラウザで実行する。保存ページのコードは実行せず、個人情報・閲覧内容・認証値も試験やリポジトリへ転記しない。

- 修正前は音量ボタンの遮蔽・時刻色・日時属性の3点で失敗、修正後は成功。
- 320px、208px、160pxのカードで音量ボタンとNG操作欄の重なりを検査。
- 音量ボタンのクリックが動画への移動を発生させないこと、コメントの描画位置が時間とともに動くこと、終了時の後片付けを検査。
- 投稿直後、24時間直前、24時間ちょうど、48時間後の色と日時属性を検査。

差分レビューでは重要な指摘なし。単体173件、ビルド・構文・情報混入検査に成功。
ブラウザ試験6種類（preview-card-integration、preview-official-contract、card-enhancements、result-layout、diagnostics、spa）に成功。

## 残る差

今回修正するのは音量ボタンを隠すNG操作欄と投稿時刻。追加カードの「あとで見る」「…」は160.21でも未実装であり、今回も公式の全操作欄を再現したとは扱わない。静的なボタン要素の複製だけではクリック時の機能まで移植できない。

複雑なコメントアートや全コマンド等の既存制限は [160.21](preview-parity-16021.md) を参照。160.22の実サイト上の表示・音量操作の確認は別途必要。
