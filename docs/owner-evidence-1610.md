# 160.10 検索結果の投稿者IDをNG判定へ補完

公開用履歴の注記: 本文の動画・投稿者識別子と検索語は架空値へ置換しています。観測資料の実値ではありません。
詳細APIが投稿者不明を返していても、同じ動画の検索結果にIDが残っている場合は、通常のID NGと複合NGで利用できるようにした。退会済み投稿者の未公開IDを取得するAPIを発見したという変更ではない。

## 変更

- 元のカード：動画IDが一致し、動画タイトルと同じ親要素にある正規の投稿者行から、プロフィールURLのユーザーID／チャンネルIDを読む。アイコンと名前の行、分析用の属性、プロフィールURLの形式を確認する。
- 追加カード：そのカードを作成した検索結果のowner情報を使う。カードと動画IDが一致する場合だけ利用する。
- 名前からIDを推測しない。説明文やメニュー内のリンク、別カードのリンク、不正なID、数値の精度を保証できないIDは使わない。
- 有効な詳細APIのIDを優先する。検索情報だけが複数のIDを示すときは、どれかを選ばず不明とする。後から投稿者不明の応答が来ても、同じ動画で既に得たIDは失わない。
- 検索結果による補完と詳細APIによる情報の出所を分ける。補完した投稿者を詳細APIのキャッシュへ書き戻さない。APIの元の応答も変更しない。別の検索で再利用するときは、その検索結果にある投稿者情報で補完する。
- 名前やアイコンも、異なる投稿者IDの行から流用しない。投稿者名が空欄・「投稿者非公開」でも、退会済みと断定する表示にはしない。
- 新しい通信、認証設定、NG保存形式の変更はない。通常のID NGは詳細APIの到着前から反映できる。タグなどの未取得情報を推測して確定しない。

## 検証

自動テスト106件が通過。専用Chromeの投稿者補完試験・カード表示試験・SPA試験と構文確認が通過した。

投稿者補完試験では、添付の検索カードHTMLをテスト用に加工し、詳細APIに投稿者IDがない状態を再現。同じIDの2本をNGにして別IDの1本を残すこと、解除、追加の投稿者通信がないこと、説明文・別動画・矛盾した行の除外、実際の追加カード生成からモデルへの反映を確認。別検索と永続キャッシュに補完情報を混ぜないことも検証した。

専用Chromeは空のプロファイル、架空のURL、すべての外部通信をテスト応答に置き換えている。実ニコニコへの接続、Tampermonkeyへのインストールは未実施。

## 残る制限

- 対応する検索結果の解析時に存在する投稿者情報が対象。ID自体が検索結果にない場合は補完できない。未対応のカード構造は推測せず不明のままにする。
- ユーザーが提示したsm90001002の実際の投稿者IDは未取得。iPhone／Webの投稿者非表示APIの仕組みは未確認。
- アプリ本体解析、追加カードのあとで見る・動画メニュー・動画とコメントのホバープレビューは未完了。実サイト操作は以前のサイト安全判定による拒否で停止している。
