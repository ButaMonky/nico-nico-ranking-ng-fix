# 追加カードのホバープレビュー設計

## 要求と境界

利用者の依頼：公式検索カードの操作を悪化させず、自動追加カードでも動画・コメント・音量ボタンを使えるようにする。高速化を重視し、マウスオーバーするまで読み込みを開始しない。ページ全体の先読みは0、短い通過も0。同時再生1件。

研究の根拠は niconico-api-research PR #11、commit b68c2ae11ce8277f0cb62a8e1081c25a6aa24ace。保存公式版の経路は判明したが、現行サイトの認証・CORS・期限・音声とコメントの完全な一致は未確認。試験機能は既定OFF、利用者が明示的に有効化した場合のみ通信する。サイト制限をGM通信等で迂回しない。

## 構成

- PreviewData：preview、再生権限、コメントをブラウザfetchで取得。型・ID・公式URL・期限を検査。認証値・署名URLはメモリだけ。失敗時に繰り返さない。
- HoverPreview：追加カードのみに委譲イベントを使い、200msのホバー待ち後に1セッションを作成。公式カードは操作しない。各非同期処理はセッションと動画IDを照合する。
- HLS.js：版とhashを固定して同梱し、実際のホバー時だけ初期化する。外部ライブラリの追加取得でページ初期処理を待たせない。ブラウザの再生制限を回避しない。
- コメント：メディア時刻から描画。文字列をHTMLとして扱わない。件数・行数を制限し、公式の完全な描画互換とは表示しない。取得したNG情報を安全に適用できない場合はコメントを表示しない。

離脱、別カード、画面外、hidden、pagehide、SPA、カード除去、動画ID差替え、NG非表示、設定OFFで自分の通信を中断し、再生・HLS・描画・イベントを破棄する。公式のvideoやobject URLに触れない。再読み込み時はミュート。音声は明示ボタンで切替。キー・メディアの永続キャッシュは導入しない。

診断は段階別通信回数と状態別件数のみ。URL、ID、検索語、名前、コメント本文、認証値、任意エラーを公開ログに残さない。メディアセグメントの転送数と制御API数は別と明記する。
