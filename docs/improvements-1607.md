# 160.7 高速化・NG表示改善（2026-09-09）

## 今回の変更

- 広告カード自体が動画リンクになっている場合、▼のクリックを「新しいタブで開く」が先取りしないよう修正。広告カードの下部に28pxの操作用余白を確保。▼の26×24pxの押せる範囲と前面表示を維持する。投稿者アイコンや名前内のマーカーを押したときも、投稿者へのリンクとして扱う。
- NG動画を表示中、カードを赤い点線で囲む。既存の非表示クラスに連動するCSSなので、NG表示の切り替え専用の監視や全カードへのスタイル書き込みを増やさない。
- ▼で開く詳細にNG理由を表示。タイトル・投稿者名の一致部分、該当タグ、タグ数・ロックタグ数・ページ内投稿数をマークする。複合NGではルール名と条件式を表示。NOTや「存在しない」条件には一致文字列がないため、無関係な文字列をマークしない。数値のマーカーは複合ルールの判定対象を示す。
- 最初からあるカードと追加カードの詳細投稿者欄に、丸い24pxアイコンと名前を表示する。元のアイコンがあれば利用。情報なし・非公開・明示された削除済み表示は灰色にする。取得失敗や空欄だけで「削除済み」と断定しない。
- SPA中は元のページ番号とリンク先を維持し、走査済みの番号に斜線、そばに範囲の説明を表示する。再描画後にも付け直す。次へリンクのスキップ・番号の圧縮はSPA OFFの従来モードに限る。
- 複合NGに「同じ投稿者の動画数（元の1ページ）」を追加。広告・関連動画を除く元の検索結果をNG判定前の件数で数える。追加候補は取得元のページごとに数え、重複動画を除外し、ユーザーとチャンネルを別に扱う。投稿者が不明な動画を含むページは件数を未確定とし、NOTでもNGにしない。この条件を有効にした検索では、元のページ単位を保つためAPI方式から従来方式へ切り替える。取得方式の変更は次の検索移動または再読み込みから反映する。
- 設定バーの配置先から動画カード・独自の詳細欄を除外し、誤挿入を防ぐ。
- 設定説明を、効果・通信量・反映タイミングが分かる文章に変更。説明を常時表示し、入力欄と関連付けた。

## 高速化と測定

- 同じdocument内のSPA移動で、成功した詳細情報を2分・最大512件だけメモリに保持する。期限切れ・失敗は再利用しない。NGの最終判定は保存せず、現在の設定で判定する。情報更新が最大2分遅れる場合がある。従来の任意のsessionStorageキャッシュは別機能。
- 同じルールJSONの解析結果を最大8設定分だけ再利用する。設定編集用の解析結果は共有しない。
- ホバー中の一時的な動画・canvas・ツールチップの変更を、カード全体の解析対象から外す。必要な変更は1描画フレームにまとめる。非表示状態の保存と、Reactによるカードの置き換えは維持する。
- 処理が終わって待機中の進捗タイマーは、全カードの再集計を省く。投稿者情報が不明な共通オブジェクトには動画の購読を追加しない。

`node scripts/benchmark-rules.mjs` による直前版661322fとの比較：60タイトル、8ルール（各2条件）、6,000判定、交互に5回測定した中央値は **181ms → 77ms（約2.35倍）**。NG判定のCPU処理だけの値であり、実サイト全体の表示速度や通信待ち時間を測定したものではない。

ChromeのSPA試験では、同じ動画が別の検索結果に再登場しても追加の詳細情報通信が発生せず、設定変更後は現在のNG設定で判定することを確認した。

## 検証

- 自動テスト99件。未確定のページ件数・NOT、ルールキャッシュの設定分離、否定条件の理由表示を追加。
- `scripts/test-spa.mjs`：検索・戻る・進む・遅延応答・処理中断・同一動画の詳細情報再利用。
- `scripts/test-result-layout.mjs`：リスト／タイル、NG状態とDOMの保持、重複防止。
- `scripts/test-card-enhancements.mjs`：添付された広告カード全体とホバーHTMLを利用。▼のクリック・四隅の当たり判定、NG理由とマーカー、アイコン維持、ページ別件数、投稿者不明、ページ番号の再描画、元のホバーボタンのイベントを妨げないこと、設定説明を確認。
- Chrome試験は専用の空プロファイル・架空のURLで行い、通信をすべてテスト応答へ置き換える。実ニコニコ、ログイン、ユーザーのChromeプロファイル、実APIは使わない。画像・サイトCSSの完全再現ではない。

## 未完了と調査結果

**追加カードの「あとで見る」「メニュー」「ミュート」、動画・コメントのホバープレビューは未実装。** 元のカードが持つボタンを妨げない修正と、追加カードに機能を再現することは別である。

添付HTMLにはボタンの形はあるが、クリック時の処理、プレビューの動画URL、コメント取得情報は含まれない。DOMをコピーしてもReactのイベントや再生状態は移らない。実サイトのChrome操作はサイト安全判定で拒否され、迂回せず停止している。動作しない飾りのボタンは追加していない。

調査候補として、ZenzaWatch関連の開発者が公開した[API一覧](https://github.com/kphrx/nico-zenza/issues/25)に、動画のタグ取得、あとで見るへの追加、シーンサーチ画像、動画アクセス権、コメント取得が記載されている。これは公式の現行仕様の保証ではなく、公開実装側の資料である。

- タグだけの取得を使えば通信量を減らせる可能性があるが、ロック・投稿者情報の充足と現行応答の確認が必要。
- シーンサーチ画像は軽いプレビュー候補だが、音声やコメント付きのネイティブプレビューとは異なる。
- あとで見るは認証を伴う書き込み。実装する場合はユーザーのクリック時だけ実行し、成功・失敗・取り消しの扱いを確認する。
- 動画とコメントのプレビューは、遅延開始・同時再生1件・マウスアウト/SPA移動時の中断と解放が必要。現在の検索画面が使う公開JavaScriptとプレビュー専用の応答を確認してから実装する。

残りの調査には、Chromeの実サイト接続が利用可能になるか、ユーザーが取得した該当機能の公開JavaScript／認証情報を除いた応答例が必要。Cookie、Authorization、視聴用キーを含むHAR全体は不要。

Tampermonkeyへのインストールと実サイト動作確認は未実施。利用する場合は生成ファイルの160.7へ更新後、一度だけページを再読み込みして新しいコードを起動する。
