# 160.23 追加カードの公式操作

目的: 追加カードの右上に「あとで見る」「…」と既存の音量ボタンを公式と同じ順序で並べ、提供されたメニュー4項目を動作させる。利用者は資料確認後に実装を承認済み。

根拠: 保存HAR内のMutedVideoThumbnail、root、enum、Format、検索ページの公式コード、および利用者が貼り付けた開いたメニューのHTML。原本や認証値、閲覧履歴はリポジトリへ追加しない。サイトの実操作や通信再送は行わない。

## 実装計画

- [x] `src/data/card-action-data.js` に公式の「あとで見る」登録、投稿者ミュート状態取得・設定を実装。正常・重複・未ログイン・異常応答・中断を単体試験で確認。通信はクリックした操作に限定し、書込みを自動再試行しない。
- [x] `src/ui/card-actions.js` に追加カードだけのボタン・メニュー・共有画面を実装。クリック、キーボード、外側クリック、狭い画面、ルート終了時の後片付けを検査。
- [x] ListPageの追加カード作成・取得時に、動画ID・確かな投稿者ID・その取得ページの公式playlistを引き継ぐ。公式ミュートはスクリプトのNG設定と混同せず、成功後は解除可能な非表示枠を使う。
- [x] Bootstrapでルート単位に開始・終了し、既存プレビューの音量・読み込み表示を3段目へ移す。プレビューOFFでも2つの操作ボタンは使える。
- [x] 全単体試験、カード・プレビュー・一覧・SPA・診断の関連ブラウザ試験、構文・プライバシー検査、別担当による差分レビューを実施。
- [x] 160.23の配布ファイルと確認手順をローカルに保存。GitHub未送信。

## 動作上の判断

- 共有は公式のURLコピーとXの投稿作成画面を開く操作。自動投稿はしない。
- ニコニ広告は公式の広告作成画面を開く操作。広告購入は行わない。
- 連続再生は取得した検索ページの `response.page.playlist` を使用。元の検索条件を推測して組み立てない。公式contextが得られない取得方式では、その項目を表示しない。
- 今回の検索ページにない「興味がない」項目は追加しない。元の公式カードと公式Reactの内部状態は書き換えない。
- 未ログインや通信失敗は成功と表示せず、固定メッセージで案内する。ユーザーのアカウントへの実際の登録は、導入後に本人がボタンを押したときだけ発生する。

## 検証と制限

- 全単体183件に成功（今回の通信契約9件、公式playlist引継ぎ1件を含む）。
- ブラウザ9種類: card-actions、preview-card-integration、preview-official-contract、hover-preview、preview-boundaries、card-enhancements、result-layout、diagnostics、spa。
- card-actionsは実カード生成と既存プレビューを組み合わせ、3段のボタン配置、クリック、コピー、ログイン案内、失敗、非表示と解除、後発カードの状態、DOM再利用、実ResultLayoutによる一覧復元、ページ終了時の中断を検査。
- マスクは元の詳細欄・広告バッジも隠し、元要素をinert化する。解除とdisposeで元のinert状態を復元する。
- 独立差分レビューの指摘を修正し、再レビューで追加の重大な指摘なし。
- 実サイトへのアクセス・実アカウントへの書込みは試験していない。提供された保存資料を根拠にし、通信は全て合成応答に置き換えた。実際の認証・CORS・サーバー仕様の変化は導入後の確認が必要。
- 共有画面はURLコピーとXの投稿作成機能を実装した独自画面で、公式ダイアログの全外観・全導線の完全複製ではない。広告は別タブを開く。
- 公式ミュート後の即時表示変更は追加カードに限定する。既存の公式カードは再読み込み後にサイト自身が反映する。
- 公式playlistがない取得方式では連続再生を省略。投稿者IDが確定しないカードでは投稿者非表示を省略する。
- 生HAR・保存HTML・実動画ID・検索語・認証値は製品や試験へ追加していない。GitHub未送信。
