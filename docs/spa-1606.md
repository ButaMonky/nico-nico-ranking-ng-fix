# 160.6 SPA移動対応

検索・タグ・ページ番号・並び順・絞り込みなど、ニコニコが同一document内で処理する遷移に合わせて、NG判定を開始し直す。従来の120ミリ秒後の `location.reload()` と、次ページリンククリック時の `location.href` 代入を廃止した。

## 動作

- History API、戻る・進む、URL監視とDOM変更を組み合わせ、リンクの文言や個別URLに依存せず遷移を検知する。hashだけの変更は無視する。
- 古い画面のThumbInfo、AutoFill通信、タイマー、イベント、DOM監視、設定への購読を解除する。遅れて届く応答も破棄する。
- 新しい結果の描画を待って、現在の設定・NGリストで判定と自動継ぎ足しを開始する。設定はdocument内で共有し、画面移動時の保存操作はしない。
- 検索・タグ・ジャンルランキング以外ではNG処理を終了し、対象画面へ戻ったとき再開する。
- ZenzaWatchが検索カードを残したまま動画URLへ変更する場合は、その画面の状態を維持する。カードが破棄された通常の動画画面への移動とは区別する。
- 同じカードの再利用時には、古い詳細表示とNG装飾を取り除いて判定し直す。

## ページ番号の扱い

SPA設定がONの間は、ニコニコ本来のページ番号リンクを維持する。AutoFillによる「取得済みページを飛ばす」「ページ番号を間引く」変更は休止する。リンクの見た目のhrefだけを書き換えても、React側の遷移先は古いままになり得るため。

ニコニコ自身が通常のページ読み込みや新しいタブを使うリンクまで、独自ルーターへ置き換える変更ではない。動画を新しいタブで開く設定も引き続き有効。

## 確認と制限

2026-09-09の確認結果：自動テスト96件成功、SPAのChrome模擬ページ試験成功、既存のリスト／タイル表示試験成功、生成スクリプトの構文チェック成功。

Chromeで保存済みのリストHTMLを使用し、全ユーザースクリプトを実行するオフライン試験を追加した。ユーザーのChromeプロファイル、ログイン、実ニコニコサイト、実APIは使用しない。

`scripts/test-spa.mjs` で確認する内容：ネイティブリンクのクリック、検索変更、History更新の前後の描画、繰り返し遷移、プレイヤー復帰、ThumbInfoとAutoFillの中断・遅延応答、同じカードの再利用、0件表示、対象外への移動と復帰、設定を書き換えないこと、詳細ボタンや設定バーの重複がないこと。

`tests/navigation.test.mjs` では連続した遷移の世代管理、popstate、URLポーリング、hash、設定OFF/ON、保存されたZenzaWatchの履歴操作も検証する。

実ニコニコサイトへのブラウザ操作はサイト安全ポリシーにより拒否された。別の操作方法で回避せず、保存済み構造での検証を行った。そのため、実サイトの全リンク、Tampermonkeyの実行環境、Reactの全描画パターンの確認は未実施。URLだけ変わって結果DOMが更新されない場合は、新結果の描画待ちとなる。

## 実サイトでの確認手順

1. 160.6へ更新して検索画面を一度再読み込みする。
2. 検索語、タグ、並び順、絞り込み、ページ番号を変更し、画面全体の再読み込みなしでNG判定が始まることを確認する。
3. 読み込み途中で別検索へ移動し、「戻る・進む」も試す。
4. ZenzaWatchを開閉し、元の結果・詳細表示が維持されることを確認する。
5. 問題がある場合は、移動前後のURL、クリックしたリンク、表示の状態を記録する。検証中の版として160.5のバックアップを保持する。
