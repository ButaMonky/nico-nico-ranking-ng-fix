# 160.14 残存する投稿者名の補完とキャッシュ改善

投稿者が非表示になった動画でも、同じ投稿者の名前を取得できれば、詳細欄へ表示し、既存の投稿者名NGに使う。hiddenを退会と判定しない。研究ブランチとは分離した製品変更で、既存の研究資料だけを参照した。

## 名前の採用条件

- 詳細APIの投稿者IDを優先し、名前がnullの場合だけ、型・IDの一致した検索情報の名前を補う。既知の名前や確認済みの空文字は上書きしない。
- 初期ページのserver-responseにある検索結果のowner情報を、動画IDが一致するカードへ一度だけ適用する。検索切替後に残る古いメタデータは再利用しない。同じ動画で異なる投稿者IDが重複する場合は不採用。
- 名前が未知で、別の情報からuser型と有効なIDを確認済みの場合に、ニコニ広告の既存contentエンドポイントを利用する。動画IDとownerIdの一致、応答形式、targetUrlがある場合の一致を検証する。
- 広告APIの数値ownerIdだけではuser/channelを判別できないため、未知型・channelへ名前を流用しない。IDだけの応答から投稿者を新設しない。名前の推測もしない。
- 詳細・検索で名前が得られた場合はそちらを優先する。広告由来の名前には「広告情報に残る投稿者名（現在の名前とは異なる場合があります）」と表示する。取得できないときは「投稿者名不明」とする。

## 通信とキャッシュ

- 既知の名前は追加要求0回。名前補完と広告装飾で同じcontent要求を共有する。既にNGと判定済みのカードは、詳細を開いた場合以外は名前の追加補完を省く。
- 追加補完は1画面につき最大64件、既存の広告用待ち行列で同時4件まで。待ち行列を含めて8秒の期限を設け、同じ動画への自動再試行をしない。SPA移動で中断し、古い応答を採用しない。
- 投稿者名の補完待ちも初期NG判定・追加候補の確定待ちに含める。詳細取得直後のイベントと名前取得開始の間で、未判定のカードを確定してしまう競合を修正した。
- セッションキャッシュの復元を、個別の詳細通信を開始する前に実施する。初期カードも保存する。メモリにある詳細情報を復元済みの場合でも、別に保存された補完名を復元する。
- 名前だけの取得結果も独立して保存する。名前しかない記録からタグ・ロックタグ・説明文を取得済みにしない。名前の有効期間は10分以内。既存のキャッシュ設定を尊重し、読んだだけでは詳細や名前の取得日時を延長しない。
- 投稿者名が取得できても、必要なタグ等が未知なら詳細通信する。AND/OR/NOT・notExistsの未知判定、設定変更時の再評価、既存の取得元優先順位を維持する。

## 匿名診断

通信分類に`network.run.ownerName`を追加。`ownerNameRecovery`に既知・広告由来・待機・採用・不採用・失敗・型未確認・予算上限・キャッシュ復元を件数で示す。広告装飾と要求を共有した場合は実際に要求した側の分類に計上し、二重加算しない。

`ownerNameRecovery`は現時点のカードの状態を表す。例えばNG設定変更で新たに補完対象となる場合もあるため、累積要求数とは異なる。名前そのもの、動画・投稿者ID、検索語、URL、Cookie、認証値、PCパスは共有レポートへ含めない。実サイトの生データや提供されたレポートはリポジトリに保存しない。

## 検証

Node.jsの自動テスト147件、構文検査、個人情報パターン検査。外部通信を模擬した隔離ブラウザでは、投稿者名・項目別取得・投稿者情報・SPA・一覧レイアウト・カード表示・匿名診断の7スイートを確認する。専用の投稿者名スイートは`node scripts/test-owner-names.mjs`で実行する（Playwrightとブラウザが必要）。

通信モックで確認した例：

| 条件 | 詳細要求 | 名前補完要求 |
| --- | ---: | ---: |
| 名前とタグが未知で、タグNGあり・初回 | 1 | 1 |
| 上記を同じタブで再読み込み | 0 | 0 |
| 投稿者IDは既知、名前未知、詳細項目を必要としない初回 | 0 | 1 |
| 名前のみのキャッシュを再読み込み | 0 | 0 |

名前が表示とNG判定に反映され、設定解除で表示に戻ること、補完中に処理完了としないこと、古いSPAメタデータを拒否すること、名前のみのキャッシュでタグは未知のままであることを確認した。20件の遅い補完要求の試験では、待ち行列を含む期限で全件が終了し、未開始の16件は通信しない。別レビューで見つかった待機の競合・期限・部分キャッシュの問題を修正し、回帰試験を追加した。

実サイトで160.14の速度・名前補完率は未測定。提供された160.13の匿名レポートでは詳細要求112件と39件、全体時間約39.4秒と31.9秒だったが、対象動画数が447件と449件で条件が同一ではない。今回の変更の効果とは扱わない。

## 残る条件と次の単位

実サイトで初回と再読み込みを比較し、`ownerNameRecovery`と名前補完・広告・詳細通信の時間を確認する。投稿者型やIDが不明な動画、APIに名前が残っていない動画、期限・上限に達した動画の名前は未知のまま。全ての退会済みアカウントの復元や現在名の取得は保証できない。

次の実装単位は、この結果を基にした名前補完と広告確認の要求計画の調整。Snapshot一括補完・playlist/request一括補完は別の候補として残し、今回導入していない。解析資料の追加調査やZenzaWatch制作も行っていない。
