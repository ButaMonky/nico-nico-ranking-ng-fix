# 160.29 — キャッシュの鮮度・通信・補充・プレビューの改善

2026-10-24。ZenzaWatchの固定版を調べた際の「参照時刻と取得時刻を区別する」「投稿者の型・ID・名前を分離する」という知見を、ランキングNGの既存処理へ適用した版です。ZenzaWatchのコードやユーザーの視聴キャッシュを取り込む変更ではありません。

## 変更

- キャッシュの取得時刻が欠落・不正・未来の場合、現在時刻を代入して鮮度を延ばさず、通常の不足情報取得へ戻します。壊れたタグ名・ロック値は復元前に拒否し、一部だけ状態が更新されることを防ぎます。
- 短期キャッシュは元の取得時刻を保持し、出典をcacheとして記録。時計が取得時点より前へ戻った場合は再利用しません。NG判定と理由をメタデータへ保存せず、現在の設定で再評価します。
- 投稿者のID・名前・公開状態を部分更新するとき、保持した旧情報の取得時刻・出典を新しいIDのものへ置き換えません。キャッシュ往復でも項目別の取得時刻を引き継ぎます。
- 投稿者補完の一時的な通信失敗を、完了済みの共有結果として固定しません。後から必要になった補完で再取得できます。既存の試行回数・通信予算・正常な404の短期キャッシュは維持します。
- 通信待機用の中断リスナーを開始・破棄時に解放します。SnapshotのHTTP200でも本文不正は取得成功と診断しません。
- Snapshot専用モードで事前NGに該当した候補も順序を保って保持し、NG解除時に戻せるようにします。
- 別カード内でマウスが動き続けても、前のプレビューの退出待機を延長しません。同じカードの子要素へ移るたびに開始待機をやり直すことも防ぎます。
- プレビューが初回描画で終了条件に達した場合、その後にコメント通信を開始しません。

## 維持する契約

通常クリック、ZenzaWatchによる履歴だけの変更・復帰、NGの保存形式、投稿者のuser/channel分離、未知を非該当としない三値判定、ホバーの200ms退出待機と300msフェード、既定OFFのプレビューを維持します。UIの意匠・公式の再生キューを独自仕様へ置き換えていません。

| 点検領域 | 今回の扱い |
| --- | --- |
| 詳細・投稿者キャッシュ | 不正値の拒否、元時刻の保持、判定結果の保存除去を修正 |
| 投稿者補完・通信キュー | 失敗からの復旧、項目別出典、中断リスナー、応答検証の診断を修正 |
| NG・自動補充 | Snapshotで除外した候補の保持・解除時復帰・設定通知を修正。既存の三値判定を維持 |
| ZenzaWatch併用の履歴・SPA | 保持DOMで再起動しない契約、通常遷移での停止、遅い応答破棄を既存回帰で再確認 |
| プレビュー・音量・コメント | ホバー開始/終了待機と終了後通信を修正。音量共有・コメントNG・HLSの既存回帰を再確認 |
| カード・メニュー・ページャー・ルールUI | 既存の操作・表示をオフライン回帰で確認。新しい意匠や未確認の公式仕様は導入しない |

`ownerFetchedAt`はschema3の詳細キャッシュに追加する任意の項目です。新規保存では投稿者のID・名前・公開状態ごとの取得時刻だけを保存します。旧キャッシュにこの項目がない場合は既知の値を維持し、項目別取得時刻をnullにします。タグ・本文のキャッシュ期限を本家データの最新性保証とは扱いません。
