# 160.20 サムネイル保持と公式ページ番号の表示継承

2026-09-20。ローカル修正版。NRN-001 / NRN-002。実サイトでの再生成功・公開済みを意味しない。

## 問題と変更

160.19は読み込み開始時に不透明なプレビュー層を追加し、失敗後にも残していた。160.20では読み込み中の層を不可視にし、play成功と映像フレームの準備（readyState、幅、高さ）を確認後に表示する。失敗・終了時は層も削除し、元のサムネイルとリンクを保つ。フレーム待ちのイベントも中断時に解除し、同じカードから離れるまで自動再試行しない。

利用者報告の匿名診断は開始10、再生0、preview要求10、rights要求0、コメント要求0、HTTP失敗9、中断1。最初のpreviewを通過していない。preflight 200を成功と扱わない。HTTP 400の固定エラーコード・項目名は前の開発タスクにも未受領と照会済み。

製品のactionTrackIdは独自の接頭辞＋16進乱数だった。保存公式版では英数字10文字＋下線＋ミリ秒時刻を生成する。要求形式の不一致を修正し、試行ごとに生成、previewとrightsで共用する。Cookie・認証値・追加ヘッダーを推測で加えていない。サーバーが400を返した理由の確定や、現行APIで受理されたことの実証ではない。

ページ番号の消費済み計算は変更せず、表示生成だけを変更した。元の公式navと番号・前後・省略の部品からクラス、表示属性、SVGを取得する。選択にdata-selectedを使い、独自の枠・4px角丸・余白・文字矢印のCSSを除去した。消費済み範囲の斜線と範囲表示は維持する。必要な番号・矢印の構造がない場合は独自navを生成せず、元の公式navを表示する。

元の公式nodeとReactの所有関係は保持する。生成した表示にイベントが引き継がれるとは仮定せず、通常クリックは既存ルーターへ渡し、修飾キー操作はブラウザへ残す。IDとinlineイベント属性は複製しない。ルーターが消失・失敗した場合は公式navへ戻す。

## 検証

変更前の単体166件が成功。追加試験では、読み込み中の黒い層、ページ番号の4px角丸・枠・余白の差、actionTrackId形式の不一致でそれぞれ失敗することを確認した後に修正した。

最終結果：Node.js 24.19.0でbuild・check・全単体167件・check-privacy・差分空白検査が成功。模擬ブラウザ13種類（投稿者名、投稿者証拠、項目別取得、カード表示、診断、SPA、一覧レイアウト、ページ送り、公式スタイル契約、ホバー制御、破棄境界、失敗時表示、HLS）に成功。HLSは合成映像・別音声を実エンジンで再生する既存試験で、公式配信ではない。

独立レビューで、元のリンクにある消費済み装飾を新しい未処理ページへ複製する問題を指摘された。既存の自動補充controllerによるclass追加を模した試験で再現し、複製時に除去して現在の判定から付け直した。公式rootの余白変更を追従する試験も追加。再確認で重要な未解決指摘なし。

検証途中には版番号を旧版固定した試験の更新漏れと、複数試験による同じdistの同時生成で失敗があった。版番号の期待値を更新し、生成を伴う試験を順番に実行して成功を確認した。検査条件を弱めて通したものではない。合成試験は現行サイトの成功保証として扱わない。現在ツリーのパターン検査は履歴全体の安全性を保証しない。

## 通信・性能

先読みを追加しない。OFF・公式カード・短い通過0要求、安定ホバー後の1セッション、離脱時中断という既存条件を維持。失敗時の自動再試行や同時数の増加は行わない。新しい要求形式の生成と表示修正による通信削減率・実サイト速度向上率は測定していない。

再ホバー時の有限キャッシュは未実装。同じ継続ホバー中の重複開始は抑止するが、離脱後の再ホバーは新しい試行。期限不明の認証・配信データを永続化しない。
