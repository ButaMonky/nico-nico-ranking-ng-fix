# 160.13 匿名診断と実通信の集計

160.12の項目別取得状態を維持し、実サイトで次の高速化箇所を判断するための診断を整備した。研究ブランチとは分離した製品変更。Snapshot一括補完・playlist/request一括補完の新規導入は含まない。

## 変更

- 設定の「開発者・診断」に「匿名診断をコピー」を追加。開発者モードOFFでも使える。コピーは追加通信・設定保存を行わない。クリップボード権限が使えない場合は診断文を選択し、Ctrl+Cでコピーできる。
- 通信を開始した箇所で回数を計測。詳細、ページHTML、Snapshot、広告者一覧、広告装飾を分け、通常利用と追加の比較診断を区別する。再試行・並列数・失敗・中断を記録する。
- 必要項目が既知で詳細要求を送っていない動画、キャッシュだけで補った動画、要求済み動画を分ける。「省略」を何度も加算しない。
- 項目別のknown/unknown/failedと、現在の設定・表示に必要だが未確認の項目を集計する。取得失敗を確認済みの空と扱わない。
- 初期処理時間、段階、終了段階までの経過時間、現在の表示件数、走査ページ数、キャッシュ状況を記録する。SPAで前のモデルを破棄し、直近3画面の数値だけを保持する。
- 初期処理・完了／停止・診断完了時に、`NRN_REPORT_BEGIN`から`NRN_REPORT_END`までを一つの文字列でコンソールに表示する。右下ステータスのダブルクリックでも出力できる。古い固定版番号を160.13に統一した。
- 従来の生ログは、このスクリプト内だけで抑止。警告・エラーは件数を記録し、起動・画面初期化・比較診断の失敗は固定分類の`problemCounts`で示す。他のスクリプトやサイトのコンソール出力は変更しない。
- 広告装飾の待ち行列を画面ごとに分離し、画面破棄後の未開始要求を取り消す。実行中の取得も画面の中断に追従する。

## 集計の読み方

- `network.run.detail.attempts`は実際の要求呼出し数。タイムアウトの再試行も含む。`uniqueVideos`は対象動画の重複を除いた数。
- `detailPlan.readyWithoutRequest`は現在のモデルのうち、必要な情報が既知で、詳細通信もキャッシュ復元もしていない動画数。累積省略数ではなく、将来の詳細欄展開まで含めた通信ゼロの保証でもない。
- `detailPlan.cacheOnly`はキャッシュ復元済みかつ詳細要求を送っていない動画数。`cache.restoredAfterRequestStarted`がある場合、復元件数をそのまま節約した通信数と解釈できない。
- `missingRequired`は現在の条件・表示に必要な情報の不足。タグNGやロックタグ条件を使っている場合は、投稿者が既知でもタグが未取得なら通信する。
- `durationSumMs`は要求ごとの時間の合計。並列通信のため、画面全体の所要時間とは異なる。`terminalElapsedMs`は画面の処理開始から終了段階までの時間。手動の診断コピーまで待った時間は`elapsedSinceRouteStartMs`に含まれる。
- `network.diagnostic`は明示した比較診断・設定済みの完全診断の追加通信。「匿名診断をコピー」はここにも通信を追加しない。
- 詳細取得の`ok`はXML検証を含む。他の種類の`ok`はHTTP成功と応答本文の受信を表し、Snapshot・広告JSONの不正や広告者一覧の取得上限は別の`payloadFailures`で示す。
- `sourceComparison`は候補取得の比較と詳細要求数の見積もり。入力件数が異なり、完全な処理時間の比較ではない。`sameWorkload:false`を明記している。

## プライバシー

レポートは許可した数値・真偽値・固定分類だけを新しく組み立てる。URL、検索語、動画ID、投稿者ID、名前、タイトル、NGに登録した値、ロックタグ閾値、Cookie、認証値、エラー本文・スタック、ブラウザ情報、PCのパスを含めない。NG設定は登録件数と有効／無効だけを示す。共有ログや実サイトの生データはリポジトリに保存しない。

サイトや他の拡張機能は独自に情報をコンソールへ出す場合がある。共有するときは新しいコピー機能か、`NRN_REPORT_BEGIN`から`NRN_REPORT_END`までだけを使う。

## 検証と残作業

自動テスト137件、構文検査、成果物の個人情報パターン検査を通過。通信を模擬した専用ブラウザで匿名診断・メタデータ取得・投稿者情報・SPA・一覧レイアウト・カード表示の6スイートを確認。検証後の追加変更がある場合は同じ関連検査を再実行する。

通信モックで、投稿者情報だけで足りる初期カードは詳細要求0回、詳細欄を1枚開くと1回、タグ条件追加で不足分を取得することを確認した。匿名コピーによる通信・設定変更は0回。コピー権限拒否時の手動コピー、再試行・重複要求、旧画面の応答破棄、広告待ち行列の破棄、SPAでのキャッシュ再利用を確認した。

実サイトの新版での速度測定とユーザースクリプト管理拡張上のコピー権限は未確認。専用ブラウザの結果を実サイトの実測速度として扱わない。提供ログは設定や失敗分類の確認に使ったが、新版の通信削減を証明するものではない。

次は匿名レポートを少数の実ページで集め、キャッシュ復元と通信開始の順序、タグ取得、広告者確認、ページ追加のうち支配的な待ち時間を特定する。既存キャッシュの復元が通信開始より後になるケースは今回計測対象として残しており、解消済みとはしない。一括補完は欠落・種類・ID整合・SPA世代を守れる条件を改めて確認してから別単位で扱う。
