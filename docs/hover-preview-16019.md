# 160.19 追加カードの試験プレビューと開発記録

## 利用者への変更

160.18のページ斜線修正を含む。自動追加カードの動画・コメント・音声ボタンを試験機能として追加した。設定「自動追加」付近の「追加カードのホバープレビュー（試験機能）」で有効にする。既定はOFF。公式既存カードのプレイヤーやReact内部状態は呼び出さず、自分の追加カードだけを扱う。

約200msマウスを乗せ続けてから読み込みを始める。先読み0、短い通過0、OFFと公式カード0、同時再生1。利用可能な低ビットレート映像・音声を選び、最大30秒で停止する。最初はミュート、音声ボタンの操作で切り替える。音量は控えめな固定値0.3、サイトの音量設定は変更しない。再訪問は先頭から取得し直す。再生キャッシュは次の単位とし、期限不明のキーを保存しない。

離脱、画面外、タブ非表示、カード除去、NG非表示、動画ID差替え、SPA、pagehide、設定OFFで自分の通信・動画・HLS・コメント描画を停止する。タブ復帰だけで勝手に再生しない。遅い応答が戻っても世代・カード・IDが異なれば採用しない。読み込み12秒、コメント8秒、再生停滞等に45秒の上限を設ける。自動再試行はしない。

## コメントの範囲

メディアの時刻に合わせた簡易canvas表示。最初の30秒にある最大300件から、4行・各4秒の空き枠に表示し、混雑時は省略する。原文をHTMLとして解釈しない。字体・色・特殊コマンド・公式の衝突処理の完全互換ではない。

公式の投稿者・チャンネル・視聴者コメントNGが非空、または未知の形式なら、NGを無視せずコメント取得・表示を止めて映像だけを再生する。既知のAIフラグと負のスコアも除外するが、公式AI判定と同等とは主張しない。空コメントと取得失敗は区別し、コメントだけ失敗しても映像は継続する。

## 高速化と通信の区分

表示カード全件へのプレビュー要求は行わない。通常の安定ホバーはpreview・再生権限・コメントの制御APIが各1回（コメント省略なら2回）。OPTIONS、manifest、メディア断片、鍵取得は別であり「全通信3回」ではない。HLSのバッファ設定は先読みを抑えるためで、厳密なバイト数の上限保証ではない。

HLS.js 1.6.19完全版をハッシュ固定して同梱し、ホバー時だけ初期化する。分離音声に対応する。追加の外部スクリプト取得で初期NG処理を待たせないが、配布スクリプトのサイズは増える。既存NGの速度が何倍になった、という計測はしていない。

匿名診断の `current.preview` に、開始・再生・停止・制御API段階別要求・失敗の件数を追加。URL、名前、動画ID、コメント本文、認証値、任意エラーを記録しない。メディア断片の通信数は含めない。

## 根拠・未確認条件

保存公式版の研究資料：[研究PR #11](https://github.com/ButaMonky/niconico-api-research/pull/11)、commit `b68c2ae11ce8277f0cb62a8e1081c25a6aa24ace`。HLS.jsは [公式ソース](https://github.com/video-dev/hls.js/tree/v1.6.19) と [API](https://hlsjs.video-dev.org/api-docs/hls.js.hlsconfig) に従う。manifestのdeliveryと断片のassetホスト分離には [公開された通信報告](https://github.com/yt-dlp/yt-dlp/issues/12495) も参照したが、署名URL等は保存しない。

ニコニコへの新規実通信は行っていない。現在のログイン・CORS・期限・actionTrackIdの受理条件・userscript環境での再生・音声・コメントの見た目は未確認。CookieやOriginを偽装せず、ブラウザfetchを利用し、CORS失敗をGM通信へ切り替えて回避しない。実ページでの少数確認が必要で、既定ONにはしていない。
